## Архитектура
Задача реализована в виде трех микросервисов:

### 1. API Gateway
- **Ответственность**: Единая точка входа для всех клиентских запросов, маршрутизация запросов к соответствующим микросервисам
- **URL**: `http://localhost:5001`
- **Swagger URL**: `http://localhost:5001/swagger/index.html`

### 2. File Storing Service
- **Ответственность**: Хранение и выдача файлов
- **Функциональность**:
  - Загрузка и сохранение файлов
  - Хэширование текста файла для обнаружения коллизий
  - Выдача текста файлов по id
- **Хранилище данных**: 
  - Метаданные: PostgreSQL
  - Содержимое файлов: файловая система (папка FileStorage)
- **URL**: `http://localhost:5002`
- **Swagger URL**: `http://localhost:5002/swagger/index.html`

### 3. File Analysis Service
- **Назначение**: Анализ текстовых файлов и выявление плагиата
- **Функциональность**:
  - Подсчет количества абзацев, слов и символов
  - Обнаружение 100% совпадений (плагиат)
  - Сохранение результатов анализа
- **Хранилище данных**: 
  - Результаты анализа: PostgreSQL
- **URL**: `http://localhost:5003`
- **Swagger URL**: `http://localhost:5003/swagger/index.html`

### 4. Common
- **Назначание**: Библиотека с общими моделями, используемыми всеми сервисами

### Сценарии использования:

#### 1. Загрузка файла
1. Клиент отправляет файл через API Gateway
2. API Gateway перенаправляет запрос в File Storing Service
3. File Storing Service проверяет наличие коллизий по хэшу
4. Если коллизия найдена, возвращаются метаданные (в том числе id файла)
5. Если коллизия не найдена, файл сохраняется в файловой системе, а метаданные — в базе данных
6. Метаданные файла возвращается клиенту

#### 2. Анализ файла
1. Клиент запрашивает анализ файла по id через API Gateway
2. API Gateway перенаправляет запрос в File Analysis Service
3. File Analysis Service проверяет наличие результатов анализа в базе данных
4. Если результаты не найдены, запрашивается текст файлаа из File Storing Service
5. Выполняется анализ текста и проверка на плагиат
6. Результаты сохраняются в базе данных и возвращаются клиенту

#### 3. Получение содержимого файла
1. Клиент запрашивает файл по id через API Gateway
2. API Gateway перенаправляет запрос в File Storing Service
3. File Storing Service находит файл и возвращает текст файла

## Обработка ошибок
Система включает обработку ошибок для следующих сценариев:
- Недоступность одного из микросервисов
- Файл не найден
- Некорректный формат файла (не .txt)

## Спецификация API

### API Gateway (`http://localhost:5001`)

#### Загрузка файла
- **URL**: `/TextScanner/upload`
- **Метод**: `POST`
- **Параметры**:
  - `file`: текстовый файл (формат .txt)
- **Ответ**:
  - `200 OK`: файл успешно загружен
    ```json
    {
      "id": "айдишник",
      "name": "filename.txt",
      "hash": "хэш",
      "location": "file_path"
    }
    ```
  - `400 Bad Request`: неверный формат файла
  - `503 Service Unavailable`: сервис хранения файлов недоступен

#### Анализ файла
- **URL**: `/TextScanner/analyze/{fileId}`
- **Метод**: `GET`
- **Параметры**:
  - `fileId`: айдишник файла
- **Ответ**:
  - `200 OK`: анализ успешно выполнен
    ```json
    {
      "id": 2025,
      "fileId": "guid",
      "paragraphCount": 2025,
      "wordCount": 2025,
      "characterCount": 2025,
      "isPlagiarized": false,
      "matchedFileId": null
    }
    ```
  - `404 Not Found`: файл не найден
  - `503 Service Unavailable`: сервис анализа файлов недоступен

#### Получение файла
- **URL**: `/TextScanner/file/{fileId}`
- **Метод**: `GET`
- **Параметры**:
  - `fileId`: айдишник файла
- **Ответ**:
  - `200 OK`: текст файла
  - `404 Not Found`: файл не найден
  - `503 Service Unavailable`: сервис хранения файлов недоступен

### File Storing Service (`http://localhost:5002`)

#### Загрузка файла
- **URL**: `/Files`
- **Метод**: `POST`
- **Параметры**:
  - `file`: текстовый файл (формат .txt)
- **Ответ**:
  - `200 OK`: файл успешно загружен
    ```json
    {
      "id": "айдишник",
      "name": "kate.txt",
      "hash": "какой-то хэш",
      "location": "file_path"
    }
    ```
  - `400 Bad Request`: неверный формат файла

#### Получение файла
- **URL**: `/Files/{id}`
- **Метод**: `GET`
- **Параметры**:
  - `id`: айдишник файла
- **Ответ**:
  - `200 OK`: содержимое файла
  - `404 Not Found`: файл не найден

### File Analysis Service (`http://localhost:5003`)

#### Анализ файла
- **URL**: `/Analysis/{fileId}`
- **Метод**: `POST`
- **Параметры**:
  - `fileId`: айдишник файла
- **Ответ**:
  - `200 OK`: результат анализа
    ```json
    {
      "id": 2025,
      "fileId": "guid",
      "paragraphCount": 2025,
      "wordCount": 2025,
      "characterCount": 2025,
      "isPlagiarized": false,
      "matchedFileId": null
    }
    ```
  - `404 Not Found`: файл не найден
  - `503 Service Unavailable`: сервис хранения файлов недоступен

## Установка и запуск

### Предварительные требования
- .NET SDK 7.0 или выше
- PostgreSQL 14 или выше

### Настройка базы данных
1. Надо создать базы данных в постгре, применить миграции через dotnet ef database update

### Запуск приложения
1. Запустить через docker compose up --build      

2. Открыть Swagger для тестирования API:
   - API Gateway: http://localhost:5001/swagger
   - File Storing Service: http://localhost:5002/swagger
   - File Analysis Service: http://localhost:5003/swagger
